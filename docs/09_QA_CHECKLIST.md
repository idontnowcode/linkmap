# LinkMap — 기능 점검 체크리스트 (결과 반영본)

> 작성/실행: 2026-08-16 · 대상: `main` 브랜치(점검 중 발견된 2건 수정 반영 후)

## 검증 방법 및 한계 (먼저 읽을 것)

이 세션에는 Electron 네이티브 창을 마우스로 클릭하는 자동화 도구가 연결되어 있지 않다. 따라서 "실행을 통한 검증"은 아래 3가지 방법의 조합으로 수행했다. **시각적으로 버튼을 클릭해서 확인한 것은 아니다** — 이 점을 정직하게 밝힌다.

| 기호 | 방법 | 설명 |
|---|---|---|
| **B** | Boot | 실제로 `npm run dev`로 앱을 부팅하고 메인/렌더러 콘솔을 감시해 런타임 에러가 없는지 확인 |
| **R** | Runtime smoke | 실제 소스코드(`repositories/index.ts`, `schema.ts`, `search.ts`)를 esbuild로 그대로 번들링해 **진짜 SQLite(libsql) 파일에 대고 CRUD를 실제로 실행**하고 결과를 assert. 재구현이 아니라 원본 소스 실행 |
| **T** | Trace | 소스에서 onClick → 상태변경 → IPC → repository → DB까지 배선이 실제로 연결돼 있는지 정적으로 추적 |

### 발견 및 수정된 문제

| # | 항목 | 증상 | 조치 | 재검증 |
|---|---|---|---|---|
| 1 | 그래프 툴바 "도움말(?)" 버튼 | `onClick`이 아예 없어 클릭해도 무반응(죽은 버튼) | 검색 문법·그래프 조작법·단축키를 보여주는 팝오버로 연결 | typecheck+build ✅ |
| 2 | `LinkFormDialog` "새 태그" 인라인 생성 | Enter로 확정 시 `onKeyDown`이 `submitNewTag()` 호출 + 입력창 언마운트 → 이 과정에서 `onBlur`가 추가로 발동하면 동일 함수가 재호출되어 **동일 이름 태그가 중복 생성될 위험** | `useRef` 가드 추가: 확정 동작이 진행 중이면 재호출을 무시하도록 방어 처리 | typecheck+build ✅, DB 스모크 K2 계열 재검증 ✅ |

다른 모든 UI 컴포넌트(좌측 사이드바, 링크 목록, 상세 패널, 관계/태그/컬렉션/설정 다이얼로그, 노드 컨텍스트 메뉴)는 배선 추적 결과 **끊긴 곳 없음**.

## 결론

- 사용자가 특히 우려한 **"링크 추가 창에서 태그 신규 생성"** 기능은 (1) 실제 DB 왕복으로 생성·부여가 정상 동작함을 확인했고, (2) Enter/blur 이중 호출로 인한 잠재적 중복 생성 위험을 발견해 방어 코드를 추가했다.
- 그 외 전체 UI 버튼 중 유일하게 죽어 있던 **그래프 툴바 도움말 버튼**을 발견해 실제 기능(도움말 팝오버)으로 연결했다.
- 이 두 건을 제외하고, 코드 배선 추적 결과 다른 모든 버튼·인터랙션은 상태변경→IPC→DB까지 끊김 없이 연결되어 있음을 확인했다.
- **한계**: 마우스로 실제 픽셀 좌표를 클릭해 확인하는 시각적 UI 테스트는 이 세션 환경에서 수행하지 못했다. 애니메이션/레이아웃 시각적 어긋남, CSS 렌더링 문제 등은 이 방법으로는 잡히지 않는다. 사용자가 직접 클릭해보며 위 표의 시나리오를 따라가면 추가 확인이 가능하다.
